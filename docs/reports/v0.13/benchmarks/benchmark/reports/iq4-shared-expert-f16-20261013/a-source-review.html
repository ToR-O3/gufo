Aの採用判断：何を参考に、どこを変えたか

2026年10月13日。Gufo v0.13.0 / Orca IQ4_XS / Strix Halo。追加の推論テストや稼働構成の変更は行っていません。

設計上の採用理由はあります。Gufo公式のQ8経路が行っている「共有エキスパート専用の領域に中間値を保存し、後続の入力を保持する」処理を、IQ4にも接続しました。計算を省略して品質を落とす高速化ではなく、同じ入力を作り直す処理の削減です。一方、実測の改善は小さく、Decodeの未確定な遅延判定が1件残るため、性能面まで全面合格としたものではありません。

直接参考にした実装

Gufo公式の 62a1eb69（2026年9月21日）は、Q8の共有エキスパート用FP16中間値を x_half から shexp_half に移し、後続エキスパート用の入力を保持する変更です。v0.13.0にも継続して含まれています。今回、この公式の履歴まで確認しました。取得済み公式コミットの差分

Strataからは「生成した中間値を次の処理で再利用し、読み直し・変換し直しを減らす」という設計を参考にしました。ただしAの直接の実装見本はGufoのQ8経路であり、Strataのカーネルを移植したものではありません。Strata側の関連例は src/prefill/kernels.cu の gr_mix_r_kernel がFP32結果と16bit入力を出力する処理です。

変更前後のデータの流れ

x_half は後続の選択エキスパートでも使う入力の置き場、shexp_half はすでに確保済みの共有エキスパート専用の置き場です。ここでの一時入力の再利用は、会話を切り替えるためのRAMキャッシュとは別の仕組みです。

変更前
元の入力 x をFP16化 → x_half に保存
  → 共有エキスパートのGate/Up
  → SwiGLUの結果をFP16化 → x_half を上書き
  → 共有エキスパートのDown
  → 後続の選択エキスパート用に x をもう一度FP16化

A候補
元の入力 x をFP16化 → x_half に保存
  → 共有エキスパートのGate/Up
  → 元と同じSwiGLU・FP16変換 → shexp_half に保存
  → 共有エキスパートのDown
  → x_half に残っている入力を後続の選択エキスパートで再利用

対象経路では、元の入力に対する追加の変換を1回省ける構造です。幅2560・4096 tokenなら、その変換の論理的な読書きはFP32読み出し40MiB＋FP16書き込み20MiB。新しい保存領域を増やさず、この変換とそのカーネル起動を省きます。これはソースから数えた仕事量であり、実際のDRAM転送量やGPU時間をプロファイラで計測した数字ではありません。重い行列積自体は変わらないため、大幅な高速化は期待しにくい変更です。

初案から変更した理由

最初はQ8と同様にSwigluHalfでFP16を直接出力し、変換処理自体も融合する案でした。しかし合成入力の−0が＋0になり、中間値のビット一致条件を満たしませんでした。これは直ちに回答品質の低下を示すものではありませんが、同一計算を保つ今回の基準では不採用としました。最終候補は元のFP32 Swiglu＋FP16変換を残し、保存先の改善だけを独立させています。

採用理由と、残る条件

判断材料評価
設計上の合理性強い根拠があります。公式Q8が同じ理由で行っている入力保持をIQ4へ接続し、実モデルの対象48層で余分な仕事を減らす構造です。
精度検査範囲で合格。中間値・出力のビット一致、独立FP64積和基準、分割入力、長文12件の生成文一致、短文の同時2会話・固定seed再生成・会話キャッシュ復元を確認。
速度3回平均Prefillは32K +0.53%、128K +0.09%。32Kは3組ともプラス、128Kは2組プラス・1組−0.06%。確かな改善率とするには小さい差です。
Decode変更対象の演算経路ではありませんが、32Kの3組目に所要時間+7.01%の判定が残ります。ばらつきを示す材料はあるものの原因は未確定です。変更していないから無関係、と断定はしません。
上流追従共通ファイルにIQ4専用の分岐を追加しており、将来の衝突はゼロではありません。DenseのFP16適用条件、shexp_halfのサイズ・寿命、入力再利用の管理が公式で変わったら整合確認が必要です。公式が同等のIQ4経路を実装した場合は公式を優先して差分を整理できます。

判断：「微増の数字だけを理由に採用」ではなく、「公式設計に沿う小さなIQ4拡張で、同じ計算の重複を減らす」という採用理由があります。ただし性能上の懸念を確認し切った状態ではありません。確実に無劣化を確認してから採用するなら、未確定の32K Decodeに絞った追加確認が残ります。今回は判断材料の整理のみで追加測定・採用は行っていません。
