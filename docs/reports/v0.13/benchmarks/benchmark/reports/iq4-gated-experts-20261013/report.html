今回の判断

数値・動作の確認は合格しましたが、2026年10月13日のユーザー判断によりB1・B2は一旦不採用です。 B2単独のDecode平均はA比で32K −1.36%、128K ＋0.54%。B1＋B2は32K −1.16%、128K ＋0.11%でした。組み合わせも一貫した上積みを示しませんでした。

正式18件では、5%かつ3ms超の遅延フラグはありません。ただし、短い補助試験にはPrefill／TTFTのフラグが残ります。これらは未解明として下表に保持し、「全区間の速度が同等以上」とは判定していません。B1/B2の変更対象はDecodeで、Prefillのわずかな変動を直接の高速化効果とは断定しません。

現在の稼働・ソースは採用済みAです。候補はそれぞれ保存しています。本比較の実施時点ではCには着手していませんでした。

比較した変更

Aは採用済みの共有専門家Prefill改善です。B2はIQ4_XSのGate／Up／SwiGLUを融合します。B1はHCが作ったQ8_1を再利用し、重複する再計算を省略します。B2の追加経路はDecode／MTPの1〜8行だけで動作し、Prefillや広い行数は元の経路です。

Aのみ        再量子化 → Gate → Up → SwiGLU
A＋B2        再量子化 → Gate／Up／SwiGLU融合
A＋B1＋B2    作成済みQ8_1 → Gate／Up／SwiGLU融合

Gufo既存の融合テンプレートにIQ4_XSの分岐を追加。GateとUpを別のwaveで処理し、元のドット積の加算順を維持します。重み形式・精度・生成設定は変更していません。専門家をまたぐ並べ替えや新しい環境変数は追加していません。

測定後は採用済みAの通常運用へ戻しています。B2とB1＋B2は独立したブランチ・実行ファイルとして保存し、まだ採用していません。Prefillの観測差を、その経路を通らないB1/B2の直接効果とは断定しません。

値・動作・キャッシュの確認

IQ4_XSの640×2560、端数7×256、最大32スロットを検査。1〜8行、無効・重複スロットを含め、融合出力が元のGate／Up＋SwiGLUとビット一致。再計算と作成済みQ8_1の両方を検査し、元のCPU FP64誤差上限は変更していません。9行以上は新しい融合APIで拒否し、モデル側は元の処理へ戻ります。HCのQ8_1生成103,680 bytesも再量子化と一致しています。

正式18件で生成文・入力/出力token数・MTP提案/採用/round数が一致。C2で2会話が実際に同時処理され、逐次実行と同じ回答になること、サンプリングのseed再現、別会話を挟んだキャッシュ復帰を確認しました。全18件の正式測定はcached_tokens=0、cache_restore_bytes=0、全入力をPrefillしています。全モデルの独立teacher/logit一致を網羅した試験ではありません。

追加テストの初回失敗も保存しています。無効スロットを元のraw tiled演算にも渡し、未書き込み領域を検出しました。この演算は負のIDを意図的に書き込まない仕様です。無効スロット検査を今回のvector経路に限定し、元のPrefillの有効スロット検査と併せて再実行しました。数値許容値の変更や、B2側の無効スロット検査の削除はしていません。

測定条件

Orca IQ4_XS、Orca互換MTP、context 131072、sessions 2、RAM cache 4GiB、MTP draft 1〜7、Vision設定維持。長文測定は同時1リクエスト。温度0・seed42・thinking無効、同じ入力・同じDocker設定・同じコンパイラを使用しています。

各起動で同じ短いウォームアップを2回実施し、32K→128Kの順で測定。3巡の設定順は A→B2→B1+B2 / B2→B1+B2→A / B1+B2→A→B2。各設定を毎回新しいサーバーで起動します。測定中はビルダーと通常Gufoを停止。時間はGufoの壁時計による区間計測で、GPU単独の処理時間ではありません。Linux負荷を記録していますが、GPUクロック・温度とWindows全体の負荷は記録していません。

試験開始時の記録

通常のGufoに別の要求が届いていたため、開始前に2回延期しました。ユーザー確認後、応答完了を検出して通常Gufoを停止し、正式測定を開始しました。延期中の処理はこの比較に含めておらず、正式18件の除外・再測定はありません。
