4. A1：IQ4で残っている中間出力を省く

最初の実装候補として最も具体的。GufoのGDNにはすでに直接FP16で結果を書く機能があるが、Executor::LinearAttention側の有効条件がssm_out.type == Q8_0になっている。OrcaのIQ4経路は、GDN結果をFP32で書く → PrepareHalfInputで読み直してFP16化 → IQ4のFP16投影、という流れになる。

[G2] [G3] [G4]

StrataのGDN_NOYが使う「次段がFP16しか読まないなら最後のFP32出力を作らない」という考え方を、Gufo既存のGDN epilogueへ適用できる。SSM出力投影のIQ4_XS対応を加え、直接作ったFP16行をNativeIq4DenseF16へ渡す。StrataのGDNカーネル全体を移植する必要はない。

[S1]

2048 tokens × 6144要素のFP32中間は1層48MiB。書き出し＋読み戻しを省ければ、36 GDN層で最大約3.375GiB相当の論理メモリアクセスと変換launchを除去できる計算になる。これはDRAM実転送量や速度改善の予測ではない。キャッシュヒットや他処理との重なりがあり、常駐メモリが同じ量だけ減るわけでもない。

同様に、IQ4側のHC epilogueは現在FP32のmixedだけを書き、その後でFP16行を準備する。FP32の計算・出力は残して、同じ結果のFP16コピーを生成時に作る案もある。Q8用wide_mixer_をIQ4で無条件に有効にするのは不可。そこは正規化やHC downの数値経路まで変わる。

[G5] [G6]

検証：元のFP32積の丸めを挟んでからFP16化すること、fast-mathが融合を変えないこと、1/8/9/15/16/2047/2048/2049行の末尾、分割入力、後続全logits、MTP採否とsnapshot復元を確認する。現行のDecode経路は同じままにする。

[G7] [G8] [G16]

StrataのHC投影では行列積・後処理の融合や入力の再利用を行っている。持ち帰るべきなのは、同じ入力を使うdown/injectなどを効率よく読むこと、packed IQ4の復号・入力ロードを複数行で再利用すること、出力と後処理の余分な往復を減らす考え方。各dotの積・FMA・和の順序を保つ設計が先になる。

HCD_EXACTの「exact」はStrataのhipBLASLt/BF16経路に対する一致であり、Gufoの元IQ4＋FP32経路との一致を意味しない。そのまま移してもGufoの精度条件は証明されない。

参考の過去プロファイル：IQ4のグループ化＋WMMA段階で、小型FP32投影416.7ms（18.9%）、expert WMMA556.0ms（25.2%）、wide dense502.8ms（22.8%）、FP16変換84.9ms（3.8%）／対象scope2207.6ms。この段階は最終活性値共有前で、今回のv0.8長文測定とは異なる。最終候補用group-final-iq4.jsonはexit 137で未完了。現在の128Kの割合や移植後の加速率には転用しない。

6. A3：MoEのGPU→CPU→GPU往復を減らす

Gufoはexpertごとの件数をGPUで数え、CPUへ転送し、hipEventSynchronize後に48/64/128行などのタイル表を作り直してGPUへ送っている。一方、Strataの融合経路はcount/scan/placeとタイル処理をGPU側で進める。概念として移植する価値がある。

[G9] [G10] [S2]

ただしGufoも、件数転送の後ろへshared expertを積んでCPU計画と重ねている。待ち合わせ呼出しがあることだけでは大きな待ち時間を証明できない。既存FP16 WMMAを保ち、まずGPU上で現在と同じ表を作る案を評価する。上限gridで無効タイルを早期終了する方式、または永続gridで有効表を処理する方式を比較できる。

48層×64チャンク相当の128Kでは、ルーティングのホスト待ち合わせを約3072回通り得る。1回ごとの実際の待ちがどの程度隠れているかを測る必要がある。出力行の配置やタイル幅を変えるとコンパイラの積和まで変わることがあるので、同じルーティングで出力・stateが一致する検証を行う。

判定：CPU待ち、転送、GPU時間、wall timeを別々に測り、通常ルーティングと特定expertに偏る場合の双方で有効なら採用する。

10. 実装する場合の検証順序

  1. 現在のGufoを基準として固定。同じソース、Releaseバイナリ、モデル、toolchain、context、MTP、入力、cache履歴を保持する。GufoとStrataを同時起動しない。
  2. 現在のOrcaで処理内訳を測る。まずpp2048と16K/32K。小型FP32投影、通常投影、MoE、GDN、Attention、PLE、CPU同期、割当、snapshotを分離。過去のWSLではrocprofのagent検出が失敗したため、既存のグループHIPイベント方式も候補。プロファイル時の速度は最終性能値に使わない。
  3. A1を一つずつ実装。GDNのIQ4直接FP16出力、次にHC epilogueのFP16コピー。A2/A3は測定した支配項に合わせて選ぶ。失敗案を混ぜた大きなパッチにしない。
  4. 独立の演算検証。native_iq4_ops、gdn_ops、hc_mix_ops、routed_wmma_ops、Attention/selectorを該当箇所ごとに実行。既存の誤差限界・goldenを緩めない。
