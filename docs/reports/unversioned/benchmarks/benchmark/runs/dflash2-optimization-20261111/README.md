## 採用判断

**単一セッションで長い定型文を新規入力から再掲する用途は、DFlash2＋4,096行Prefillを採用可。常用の通常文・日本語・コード生成・JSON・ツール・思考あり・2セッションにはMTPを選ぶ。** 常用の運用変更はこの試験の範囲外。用途限定の実装は Flash-Nextの最小差分（ローカル保管：flash-next-dflash2-prefill-4k.patch）。共通のDFlash2バックエンド、精度検証、採用処理、巻き戻し、保存形式を既存のまま使う。

### 実装を残す範囲

- 4,096行Prefillは、対象モデルだけが持つ既存のPrefillパス幅を再利用する。ドラフトの実注意窓2,048トークンは維持し、同じパスで上書きされる特徴量の射影を共有インジェクターが既存の手順で省く。13.5K入力の特徴量反映は840→546 ms、Prefillは12.58→11.63秒、TTFTは13.01→12.10秒だった。
- 信頼度0.7は、短い通常文の固定幅7で22.79→32.03 tok/s。128確定トークンあたりの検証候補は365→94件、生成候補は365→445件、ターゲット実行は33.02→22.11 ms/tok。候補生成を抑える幅調整との併用も確認した。MTPの通常文完了時間を越える改善は見つからず、最小差分は4,096行の変更に絞った。
- 最終層省略は特徴量とロジットのバイト一致を確認した。単独の長文3回でPrefillが2.1〜3.9%増加し、組み合わせにも再現する独立した短縮は確認できなかった。
- 履歴一致長12、広幅検証、GPU特徴量直接参照は各々のログを残した。定型文では検証幅を広げると実行行数が増え、現行DFlash2より遅くなった。直接参照で長文の特徴量反映が短縮したのは約6 msだった。
- 共有コードの試作は 実験差分（ローカル保管：experiment-batch.patch） に保存。既存の27B長さ制御のテストと信頼度の境界・非有限値テストを通した。27Bの実モデルGPU試験は未実施。対応するターゲットとDFlash2のGGUFがそろえば、既存の `qwen_dflash_gpu_test` で再開できる。最小差分の変更ファイルはFlash-Nextの `engine.cpp` 1つ。

## キャッシュを引き継いだ追記

現行AR、MTP、DFlash2はいずれも13.5K前後の追記2件で、ライブ状態から再開した場合と新規Prefillで実行した場合のトークンが異なった。新規Prefillでは3経路の全トークンが2件とも一致した。ライブ再開位置はARが13,549と13,489、MTPとDFlash2が13,550と13,490。変更したDFlash2でも現行DFlash2と同じ箇所で差が出た。最初の相違位置と、実際に再利用したトークン数は [cache-audit.json](../../../../evidence/benchmark/runs/dflash2-optimization-20261111/cache-audit.json)。

ライブ状態にも4行境界を要求する試作では、ARとDFlash2がそれぞれ2件とも13,508または13,448トークンの保存済み状態から再開し、新規PrefillのARと全トークン一致した。DFlash2の再処理は各42トークン増え、TTFTは432→648 msと499→619 msだった。元の再開経路を広く変更する判断には、長文・編集・途中停止の回帰確認と、この費用に見合う条件の実測が残る。診断差分（ローカル保管：aligned-live-diagnostic.patch） · 再試験の生ログ（ローカル保管：raw/cache-align）

最終層省略は、現行DFlash2と34回分のターゲット特徴量・最終ロジットがSHA-256で一致。GPU入力の直接参照は、現行DFlash2と41回分のターゲット特徴量・最終ロジットが一致した。ハッシュと各回の入力は raw/state（ローカル保管：raw/state） と raw/context-state（ローカル保管：raw/context-state）。
