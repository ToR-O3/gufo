2026-11-12 JST。ToR-O3 UD-IQ4_XS＋内蔵PLE、DFlash2 Q8_0、gfx1151、WSL＋Docker・ROCm 10.1。基準は⑤の信頼度カットを採用したローカル版 `94028ef`。

## 分解計測と試作

制約なしの貪欲生成で、既存の巻き戻し呼び出し内のロジット転送、GDN状態と履歴の復元、同期待ち、ホスト内のコピーを分けて計測した。下表は各ケースのウォームアップ後１回の値。単位は確定１トークンあたりのms。同期待ちとホスト内コピーも巻き戻し合計に含む。

| 負荷 | ⑤のロジット転送・ホストコピー | 状態復元 ⑤ → ⑱試作 | 巻き戻し合計 ⑤ → ⑱試作 |
|---|---:|---:|---:|
| 通常文 | 0.164 | 1.382 → 0.308 | 1.546 → 0.473 |
| 長文 | 0.197 | 2.488 → 0.556 | 2.686 → 0.753 |
| 定型文の反復 | 0.068 | 0.300 → 0.061 | 0.369 → 0.140 |

状態復元の時間が大きかったので⑱を試作した。DFlash2の通常幅で棄却が発生したとき、各層の畳み込み履歴を既存のGDN状態復元カーネルの中でコピーする。別々のデバイス間コピーの起動を省き、読み書きするバッファ、履歴の位置、GDNの積和順序を維持する。DFlash2が全候補を採用したラウンド、広幅検証、PLEの復元、ロジット転送は既存経路を使う。GPU上の状態を書き戻す順序も同じストリームで保証する。

計測値はホストから観測した区間時間。WSLの `AMD_SERIALIZE_COPY=2` が有効で、復元区間にはコピー起動とその待ちが含まれる。⑰の転送量を減らすコードは試作範囲外。２構成のログと各ラウンドの内訳は 計測データ（ローカル保管：rollback-profile.json）。

⑤単独→⑤＋⑱の各構成３回の中央値。巻き戻しの区間計測を無効にし、トークン照合用の出力は両構成で有効にした。1セッション、コンテキスト32,768、新規Prefill、貪欲128トークン生成。2組は⑤→⑤＋⑱、1組は逆順。Decodeは同一入力の全9組で向上。組ごとの差は通常文+1.57〜6.47%、長文+2.78〜7.80%、反復+0.19〜1.13%。完了時間は通常文の全組で176〜267 ms短縮、長文の全組で74〜565 ms短縮、反復で−59〜+48 ms。Prefillの差は実測値で、変更箇所はDecode中の巻き戻しのみ。

ウォームアップを含む30/30件が同じビルドのARと全トークン一致。HIP使用量の負荷後ピークは両構成で69.55 GiB、Docker匿名RAMの差は同一ブロック内で約8 MiB以内。

## ２セッション

| 出力長 | 合計Decode tok/s | リクエスト開始からの合計 tok/s | TTFT ms | SSEの最大間隔 ms |
|---|---:|---:|---:|---:|
| 96＋96トークン | 28.05 → 29.82 | 19.24 → 20.17 | 3,831 → 3,660 | 688 → 688 |

各構成3組の中央値。合計Decodeは２件のうち最初の出力から最後の応答終了までで計算した。TTFTとSSEの最大間隔は各組2件、計6件の中央値。合計Decodeの同一入力ごとの差は96＋96で+4.45〜7.18%、32＋96で+0.21〜3.53%。実行順はAR→⑤→⑤＋⑱。貪欲生成はウォームアップを含め⑤と⑤＋⑱の各16/16件がARと全トークン一致した。

サーバーは両構成で既存の逐次フォールバックを使った。同時到着時に先に最初の出力が届いたセッションの最大間隔の中央値は、96＋96で1,037→988 ms、32＋96で970→991 msだった。後に出力が届いたセッションでは352→340 msと330→352 ms。Docker匿名RAMのピークは両構成で4.11 GiB、HIP使用量の負荷後ピークの差は2 MiB未満。セッション別の値は [２セッションの集計](../../../../evidence/benchmark/runs/dflash2-rollback-profile-20261112/rollback-c2-summary.json)。

## 精度と採用判断

- 単独と２セッションの貪欲生成は、⑤と⑤＋⑱を合わせて62/62件、試作単独で31/31件が同一ビルドのARと全トークン一致。件数にウォームアップを含む。
- シード4、温度0.7のサンプリング２件とキャッシュ４経路８件は、⑤と⑤＋⑱で全トークン、ドラフト件数・採用数・再利用量が一致。完全一致キャッシュは1,577〜1,583トークンをRAMから再利用して追加Prefillなし。続きの要求は1,673〜1,679トークンをライブ状態から再利用し、26トークンを処理した。ライブ再開と新規Prefillの続きは、ウォームアップの第2トークン、本計測の第33トークンから異なり、最初に異なるトークンIDも両構成で同じだった。[⑤採用時の同じ挙動](../dflash2-confidence-moe-20261111/README.md) · [今回の集計](../../../../evidence/benchmark/runs/dflash2-rollback-profile-20261112/rollback-state-summary.json)
- 既存のGDN演算試験に融合経路の照合を追加してgfx1151で実行。保持した各プレフィックスでGDNのFP32状態と畳み込み履歴がバイト一致し、履歴バッファの末尾のガードも保持した。GDNの積和は独立したCPU式でも照合した。全語彙ロジットは今回の実モデル計測の対象外。演算試験の差分（ローカル保管：gdn-test.patch） · 演算試験の出力（ローカル保管：raw/gdn-test.log）

**⑱は常用環境向けの採用候補。** ⑤の通常文・長文と２セッションのDecodeが改善し、反復のDecodeも全組で微増した。反復の完了時間と32＋96の合計速度の改善幅は小さい。常用のWSL環境ではコピー起動と待ちの削減が効いた。ほかのROCm環境での速度とMTPに対する差は今回未測定。⑰は転送の占める時間が小さく、分解計測までとした。
