2026-11-12 JST。ToR-O3 UD-IQ4_XS＋内蔵PLE、Flash-Next DFlash2 Q8_0、gfx1151、WSL＋Docker・ROCm 10.1。⑤のローカル採用版 `94028ef` を基準とした。

**①の取り込みは見送り。** 通常文の完了時間は各組で31〜98 ms短くなった。Decodeは順序を逆にした組で低下し、反復では全組で低下した。

## 変更と比較

⑤を有効にした同じビルドを使い、①の表だけを試験用の環境変数で切り替えた。Flash-Nextの貪欲なニューラルドラフトで、既存の候補幅選択に過去の固定幅1〜7の実測コスト表を渡す。表は⑤導入前の浅い位置で計測した相対値を使用した。信頼度は両方で0.7。1セッション・コンテキスト32,768・新規Prefill・出力128トークン。各ブロックでウォームアップし、2組を⑤→①追加、1組を①追加→⑤の順に測った。両構成の各入力は同一で、全要求でキャッシュ再利用は0トークン。

| 負荷 | Decode tok/s | Prefill ms | TTFT ms | 完了 ms |
|---|---:|---:|---:|---:|
| 通常文 約1.6K | 32.94 → 32.55 | 1,765 → 1,692 | 1,887 → 1,804 | 5,824 → 5,793 |
| 長文 約13.5K | 29.14 → 28.91 | 12,138 → 12,130 | 12,629 → 12,526 | 16,902 → 17,014 |
| 定型文の反復 約2.6K | 76.57 → 74.87 | 2,593 → 2,584 | 2,750 → 2,735 | 4,483 → 4,507 |

各構成の３回の中央値を⑤→①追加の順に記載。通常文の同一入力ごとのDecode変化は +0.86%／+2.68%／−1.42%、長文は +2.66%／−7.20%／+3.91%、反復は −2.23%／−2.23%／−1.77%。通常文のPrefillとTTFTの中央値は低下したが、①はDecodeの候補幅だけを変更するため、Prefillの差を施策の効果とは判定しなかった。

貪欲生成はウォームアップを含む30/30件で同じビルドのARと全トークン一致。既存の信頼度・候補幅テストと、今回の表で幅が変わるテストが通過した。HIP使用量の同一順序ブロック内の差は約7 MiB以内、Docker匿名RAMのピークは両構成で約4.08 GiB。WSLとWindowsの観測は別々のログに保存した。

## 長文の低下を再確認

約13.5Kのうち初回にDecodeが7.2%低下した入力を、①追加→⑤の順でウォームアップ各1回、本計測各3回リプレイした。Decode中央値は **29.69 → 27.90 tok/s**（-6.0%）。全3回で①追加が遅かった。同じ128トークンを出す間に、ドラフトラウンドは 73 → 79、検証に渡した候補は 89 → 87、採用は 55 → 48。貪欲生成はこの再試験も8/8件でARと全トークン一致した。再試験の集計（ローカル保管：deep-retest.json）
