# ゲートの NPU 分担を比較した条件

> 履歴資料：本文の採用状況・起動状態・未完了事項は作成当時の記録です。現在の仕様は共通カスタム台帳を参照してください。測定値は再集計せず保持し、個人ホームパスを匿名化しています。生ログ・個人設定は公開対象に含めていません。

2026-11-11 JST。ToR-O3 UD-IQ4_XS と内蔵PLE。Windows の Strix Halo NPU と、WSL＋Docker で ROCm 10.1 の gfx1151 を使用。Gufo は試験バイナリを一つだけビルドし、各モードは同じ Docker イメージ・同じモデル・同じ入力を使用した。通常の Gufo コンテナを試験に転用していない。

入力は前回の全投影試験と同一の実テキスト・コード。36,192 トークンをトークン化し、先頭 16,384 または 32,768 トークンを AR の単一セッションで新規プリフィル。各長さ・構成でウォームアップ１回、正式計測３回。CLI の TTFT は Prefill と最初のトークンを返す処理の和。モデル読込・トークン化・HTTP 往復・ロジット保存は計測外。ログにウォームアップと読込時間も保存。GPU イベントを記録する計測は別枠で実施。

## ログの読み方

- `npu-per-layer.csv` はプロンプト長・反復・パス開始位置・層・区画・4K グループ・ジョブ番号とコピー／XRT／通知の各時間。`windows_xrt_ms` は Windows 補助プロセスの XRT 呼出と同期を含む。純粋な NPU カーネルの実行時間は分離していない。`remote_ms` は WSL からの投入以降の Windows 実行と完了通知。`remote_minus_xrt_ms` は各ジョブの差。
- `gdn-per-layer.csv` は GPU 主ストリーム上の HIP イベント差。融合では合流前が主に畳み込み、合流後が再帰と出力処理。分離では合流前が畳み込み・準備・再帰、合流後が出力処理。`wait_ms` は NPU 完了とサイドストリーム上の BFP 展開を待つ時間を含む。CPU と GPU の時間が重なるため、ブリッジ時間や GPU 待機時間を全体の所要時間に加算しない。未測定は空欄。
- `layer-bridge-summary.csv` と `layer-gdn-summary.csv` はウォームアップを除いた層別分布。`pass-summary.csv` はウォームアップを含むパス別内訳。`summary.json` に全反復、中央値、ロジット比較とメモリ内訳。
- `logs/*-wsl.jsonl` は WSL の空きRAM・スワップ・CPU と Docker cgroup のメモリ・CPU 累積、原則１秒間隔。最初の GPU 対照は途中で Docker 計測を接続したため `gpu-docker.jsonl` に分かれる。Cgroup のメモリと HIP の空きから算出した使用量は観測範囲が異なる。Windows のワーキングセットと共有ページも重複する。
- ロジットは各正式試験の最初の計測回から、最後の入力位置で全語彙 248,320 個を FP32 で保存。KL は GPU を基準にしたソフトマックス分布の差。同一入力で最初のトークンまで確認。MTP、自由生成の品質、複数セッション、HTTP の TTFT、GPU/NPU の使用率カウンターは今回の測定外。
- `harness/gate-trial.patch` は前回の２区画試験を土台にした今回の差分。前回のベースパッチは隣の `20261111-npu-whole-two-bank/harness/two-bank.patch`。NPU の xclbin と命令は前回と同一、ファイルの照合値は `environment.txt`。
