## 同じ実行順に揃えた比較

- GPU の16K融合パスを基準にすると、NPU２区画の Prefill 差は +5.13%／+5.37%（16K／32K）。
- GPU だけの２区画と比べた NPU２区画の Prefill 差は +0.24%／-0.34%。両サイズで計測値の範囲が重なる。
- 通常の4K GPU パスから16K GPU パスに替えたときの Prefill 差は -10.61%／-12.85%。
- GPU 単一区画で GDN を分離した場合の Prefill 差は +27.01%／+31.54%。
- 同じ分離 GDN の GPU 対照に対する、NPU 単一区画の Prefill 差は +14.08%／+13.69%。
- 通常幅の4Kに戻した NPU 単一区画の Prefill 差は、通常の4K GPU 対照に対し +14.37%／+12.12%。

## GPU 合流と NPU 側の時間

正式計測とは別に、各長さでウォームアップ１回と計測１回。次の範囲は正式形状で計測した、16K プリフィルパス３つの最小〜最大。対象33層の GPU 主ストリームのイベント差を合計。２区画は各層の両区画を含む。単位は ms。

| 構成 | GDN 合流前 | ゲート待ち | GDN 合流後 |

| GPUのみ２区画 | 292.5〜304.1 | 38.4〜44.0 | 542.5〜572.1 |
| NPU２区画 | 302.0〜305.8 | 56.6〜79.4 | 533.4〜550.7 |
| GPUのみ単一区画・分離GDN | 5471.4〜5575.6 | 16.0〜19.4 | 171.0〜172.0 |

単一区画は出力処理までゲートを待たずに進める。GDN を分けると、GPU だけの場合も合流前の処理が16Kパスあたり約5.5秒かかった。２区画は融合 GDN を使ったまま大半の NPU 処理を隠した。GPU の２区画だけでも単一区画の融合 GPU より遅いため、NPU の完了待ちの削減だけでその差を埋めるのは難しい。

## 改善の検証に使うログ

- 層別の合流待ち（ローカル保管：gdn-per-layer.csv） と NPUの送受信・実行（ローカル保管：npu-per-layer.csv） に生値。パス別合計（ローカル保管：pass-summary.csv） は初回の割り当てを含むウォームアップも確認できる。
- 最初の16Kウォームアップではゲート待ちの合計が２区画で972 ms、単一区画で1,203 ms。最初の４ジョブは送信95.76〜117.26 ms、受信178.45〜218.91 msだった。定常時のコピーとの差を初回ページ利用と分けて再測定できる。
- 層ごとの前回・今回の照合（ローカル保管：layer-crosscheck.csv） は、前回の合成入力4Kでの投影単体差と今回の実モデルの GPU 待ちを並べたもの。計測範囲と行数が異なるため、差を足し引きしてモデル全体の改善量を予測しない。
- 合流待ちを詰める余地は各パスで数十 ms。既存の融合 GDN を保ったまま、ゲートの GPU からの入力作成とNPU 戻りの展開を測る価値がある。16Kパスでは対象層ごとに FP32 のゲート配列384 MiBを展開しており、その展開を融合カーネル側で消費する方法と、少数の層を対象にする方法を別々に比較できる。
- [全測定値・範囲を算出できる反復データ](../../../../evidence/benchmark/runs/20261111-npu-gate-comparison/summary.json) と `logs/` に起動・実行・CPU/RAMのログ。`logits/` は照合用FP32生データ。試験版の再現用パッチは `harness/`。

## 起動・実行失敗の記録

２区画の8K試走ではウォームアップ後、79件目の通知が15秒以内に返らず中断。単一区画の最初の正式試験は重み登録の最初の層でタイムアウト。その後、２区画と単一区画で重み登録と処理完了を確認。Windows の障害イベント照会では対象プロセスに対応する記録を検出できなかった。２区画の層別計測では開始時の Docker サンプル8件がタイムアウトし、その後取得を再開した。

計測は一時ディレクトリの試験版で実施。通常の Gufo は開始・終了とも停止状態。
