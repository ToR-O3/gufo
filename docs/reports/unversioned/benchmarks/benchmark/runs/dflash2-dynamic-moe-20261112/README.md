## 試作

⑤が決めた自動幅と累積信頼度0.7を両構成で使用。貪欲なニューラルドラフトで、ターゲットに渡す検証行数がアンカーを含めて2〜4行の場合、エキスパート順のdown投影を既定の最大8枠から4枠に変更した。対象形式はQ5_0・IQ4_NL・Q2_0で、ToR-O3の48層のdown重みが該当。1枠はルーティングで選ばれたエキスパートへの割り当て1件。gate/up・量子化・加算順序・履歴コピー・Prefillは既存経路を使う。

前回の固定幅と一律タイル縮小の試験とは、タイルを切り替える条件が異なる。今回の試験は、⑤が実際に検証へ渡した行数を参照する。同じビルドの起動設定で切り替え、2行・3行・4行の発動を生ログで確認した。[前回の固定幅試験](../dflash2-confidence-moe-20261111/README.md)

| 長文 約13.5K | 28.62 → 28.26 | 12,213 → 12,378 | 12,638 → 12,768 | 16,930 → 17,337 |

⑤単独→⑤＋⑳の中央値。各入力の正式計測は3組。先行2組は⑤→⑤＋⑳、残り1組は逆順。1セッション、コンテキスト32,768、新規Prefill、出力128トークン。通常文のDecodeは各組 +2.57%／+0.45%／+2.24%、長文は −5.98%／−1.23%／+4.81%、反復は +0.18%／+2.07%／+0.61%。通常文の完了時間は各組で5〜180 ms短縮し、反復の完了時間は各組で29〜86 ms増加した。今回のコード変更はDecodeのdown投影で適用するため、PrefillとTTFTの差は計測値として記録した。

ウォームアップを含む貪欲生成30/30件が同じビルドのARと全トークン一致。両構成で候補の検証件数と採用数は同じだった。起動時・負荷後のHIP使用量の差は最大約16 MiB、Docker匿名RAMピークは両構成で約4.08 GiB。Windows全体、VmmemWSL、WSL、Docker、HIPの観測は各スコープの生ログに保存した。

## ２セッション

| 出力長 | 合計Decode tok/s | TTFT ms | SSEの最大間隔 ms |

| 96＋96トークン | 28.41 → 27.29 | 3,806 → 3,757 | 672 → 680 |

各3組、⑤単独→⑤＋⑳の順で起動。合計Decodeは２件の最初の出力から最後の応答終了までの合計トークン数÷秒、TTFTとSSE間隔は各要求の中央値。合計Decodeは出力長が同じ場合に2/3組、異なる場合も2/3組で試作が低下した。DFlash2の両構成で既存の逐次フォールバックが動作した。全32件が同じビルドのARと全トークン一致し、Docker匿名RAMピークは両方とも約4.11 GiBだった。
