# ToR-O3 の NPU 投影別比較

> 履歴資料：本文の採用状況・起動状態・未完了事項は作成当時の記録です。現在の仕様は共通カスタム台帳を参照してください。測定値は再集計せず保持し、個人ホームパスを匿名化しています。生ログ・個人設定は公開対象に含めていません。

2026-11-11、WSL＋Docker、gfx1151、ROCm 10.1、Windows XRT。固定の追加RAM予算を置かずに、ToR-O3 UD-IQ4_XS＋内蔵PLEの実GGUFに含まれる投影を比較した。NPUの固定行列積は参考 fork の `223540e2` の xclbin と命令を使用。入出力は WSLg 共有ページとHIP固定ページをCPUコピーでつなぎ、GPUカーネルはHIP固定ページから直接展開する。

## 投影別

GPU対照は各4,096行の２区画を現行の量子化GPU投影カーネルで処理した。併用側は第１区画をGPUで処理しながら、第２区画の選択された投影をNPUに渡した。一部の投影だけを渡す場合は、第２区画の残りをGPUで処理し、両方の結果を同じ出力配列に収めるところまで計った。各層で交互に計３回、表は層ごとの中央値を足した時間。層の入力は共通の合成F16パターンで、層間状態を接続したモデル実行の計測とは範囲が異なる。

| NPUに渡した投影 | 層数 | GPUのみ | NPU併用 | 時間差 | 短縮した層 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 線形注意の全投影 `ssm_in` | 34 | 811.73 ms | 1,014.57 ms | +24.99% | 0 |
| 線形注意のQKVだけ | 34 | 811.90 ms | 810.64 ms | −0.15% | 19 |
| 線形注意のゲートだけ | 34 | 813.06 ms | 772.04 ms | −5.05% | 34 |
| 通常注意の全投影 `attn_qkv` | 12 | 230.00 ms | 257.99 ms | +12.17% | 0 |
| 通常注意のQueryとゲートだけ | 12 | 231.87 ms | 250.55 ms | +8.05% | 0 |
| 通常注意のK/Vだけ | 12 | 232.94 ms | 254.03 ms | +9.05% | 0 |
| 線形注意のゲートだけ。該当重みのみ登録して再試験 | 34 | 820.77 ms | 792.51 ms | −3.44% | 30 |

`layer-median.csv` は層と投影ごとのGPU対照、併用、送信、Windows処理と通知、受信、GPU側の残待ちと展開を収録。`samples.csv` に全516比較。`projection-accuracy.csv` は層・投影ごとに4,096要素を照合した相対RMSE等。全投影試験で相対RMSEは約1.30〜1.42%。非有限サンプルは0。

全46層の投影は700分割のBFP重みを実際に登録して完走。重みだけで2,064,384,000バイト（1.923 GiB）。共有ページを一度、HIP固定ページとWindows補助のprivate commitをそれぞれ数えると、NPU経路に帰属できる分は2.163 GiB。ゲート専用試験では204分割、重み601,620,480バイト（573.75 MiB）、同じ集計で0.709 GiB。ドライバ内部の非公開割り当ては独立計上できていない。WSLのPSSとWindowsのワーキングセットは同じ共有ページを含むため足さない。

参考 fork 本体の試験ビルドでは、テンソルなしの先頭分割を読み込む公式修正を移した後も、ToR-O3の `blk.8.ffn_down_exps.weight` のQ2_0が未対応で読み込みに失敗した。投影だけの計測はその形式に依存せず、現行GufoのGPU投影カーネルと比較した。参考 fork と同じ全モデル２区画スケジュールは未実測。

## 現行Gufoのモデル全体でゲートだけを比較

既存のGPU用スナップショット `571c6b54` に診断用のゲート経路を追加し、同じ試験バイナリ、同じ ToR-O3＋内蔵PLE、同じ入力でGPU単独と比較した。PLE後のQ6_Kゲート33層をNPUに渡し、Q8_0の1層はGPUに残した。幅4,096のプリフィルにだけ適用し、NPUの結果をGated DeltaNetの既存の合流点で消費する。実際のNPU実行は1,584回、各6分割。MTPを使わないAR。Gufo標準の繰り返しトークン列を用い、各サイズと構成でウォームアップ1回、計測3回。TTFTはCLIでプリフィルと最初のトークンを返す処理を合算した値で、HTTP経由の時間は未計測。

| 入力 | GPU プリフィル | NPUゲート プリフィル | 時間差 | GPU TTFT | NPUゲート TTFT | 時間差 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 16,384 | 11.736 s | 11.704 s | −0.27% | 11.777 s | 11.740 s | −0.31% |
| 32,768 | 22.601 s | 23.417 s | +3.61% | 22.637 s | 23.457 s | +3.62% |

16KはGPU対照の実行間のばらつきの範囲。32KではNPU併用3回すべてがGPU単独3回より遅い。同じ入力で最終トークンの全語彙248,320ロジットを比較。全て有限、上位1位と実際の最初のトークンは両サイズで一致、上位10候補中9件が一致。GPUからNPUへのKLは16Kで0.00016785、32Kで0.00001790、RMSEは0.35660と0.41685。繰り返し入力の照合であり、自由生成や長文の回答品質は別途の評価が必要。

ゲート33層の実登録は198分割、重み583,925,760バイト。共有領域の使用624,037,888バイト、HIP固定ページ40,108,032バイト、Windows補助のprivate commit 79,552,512バイト、合計743,698,432バイト（0.693 GiB）。モデル・キャッシュ・ドライバの物理RAM全体はこの合計の対象外。

最初の16K試運転で、NPU実行とWindows側の完了処理は平均7.39 ms、WSL側の通知を含めると13.05 ms。正式試験はWindows補助にプロセス内の250 µs待機タイマーを使い、それぞれ7.69 msと8.14 msだった。正式試験の入力コピーは平均0.88 ms、出力コピーは2.18 ms。試運転と正式試験の実行順・最大文脈・負荷は揃えていないため、差の全量を待機タイマーだけの効果として扱わない。[Windows API](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createwaitabletimerexw)

`model-summary.json` にウォームアップを含む全計測、メモリと精度。`logs/` に元の実行ログ、`logits/` に照合したバイナリ。`harness/gate-model.patch` は試験版の差分。全試験は一時ディレクトリと試験用Dockerで実施。常用Gufoは開始時と終了時に停止状態を確認。モデル全体の正式試験はゲートに限り、参考 fork の全投影２区画経路とは別のスケジュール。
