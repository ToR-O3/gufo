# Flash-Next の Q6_K 共有エキスパート並列化

> 履歴資料：本文の採用状況・起動状態・未完了事項は作成当時の記録です。現在の仕様は共通カスタム台帳を参照してください。測定値は再集計せず保持し、個人ホームパスを匿名化しています。生ログ・個人設定は公開対象に含めていません。

**現行の GPU 経路を採用。** 4,096行の Q6_K 並列版は単独プリフィルの全条件で遅かった。常用 Gufo は元のコンテナと起動引数で復旧し、`/health`、モデル一覧、短い生成を照合した。

## 実モデル比較

ToR-O3 UD-IQ4_XS＋内蔵 PLE。WSL＋Docker、gfx1151、ROCm 10.1、基準 `571c6b54`。稼働中の `96f1aa8c` と `src` の差分は空。比較用の２ビルドは GCC 16.2 と同じ HIP 最適化設定を使用。両版の差分は `gpu-overlap-candidate.patch` の１ファイル。常用と同じ2セッション・131,072コンテキスト・RAM キャッシュ・思考 auto。AR は投機生成オフ。

Gufo の固定入力コーパス計測で、ウォームアップを除いて各３回。新規要求は温度0、出力上限64、キャッシュ再利用を無効化。測定したすべての単独要求で、16,384トークンを4,096行×4、32,768トークンを4,096行×8で処理した。TTFT は推論テキストの開始を含むサーバー計測値。実際の表示テキストと推論テキストは別々にハッシュで照合した。

## 単層と NPU の採否

ToR-O3 の第0層の Q6_K gate/up と合成 F16 入力を使用。GPU 直列と並列の FP32 gate/up、SwiGLU 後の F16 は512行と4,096行で全バイト一致。最適化済み GPU イベント計測の15回の中央値は、512行で0.339 → 0.844 ms、4,096行で2.385 → 2.895 ms。並行負荷は実 MoE の代わりに同じ入力を読む別の Q6_K 射影。

既存の AIE BF16 行列積が要求する丸めにより、同じ実 GGUF の重みの単一要素を拾う入力でも GPU の FP32 結果と異なる。GPUの値0.031463623046875に対し BF16 の対応値0.031494140625。再利用可能な演算で全バイト一致を確認できなかったため、Q6_K の NPU 実行と接続は未実施。

## 予備試行と証跡

- 最初の比較ビルドでは共通 HIP 量子化カーネルの最適化フラグが抜けていた。前回の606.9／653.9 msは採用評価から除外し、両版に同じ最適化を入れて単層を再測定した。
- 予備試行は、Chat API で未対応のオプションを送った２セッション試験と、各ランで異なる識別子を入力に足した単一プロンプト計測を含む。修正後の固定入力コーパス計測のみを表に掲載した。
- `summary.json` に各測定値・中央値・平均・範囲・回帰フラグ、`memory-summary.json` に観測範囲・件数を収録。生の HTTP 結果・ストリーム照合記録・コンテナログ・復旧時の応答を同じディレクトリに保存した。
