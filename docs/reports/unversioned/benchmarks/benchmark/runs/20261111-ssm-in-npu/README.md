# ToR-O3 の Q6_K ssm_in を Windows NPU と分担する単層比較

> 履歴資料：本文の採用状況・起動状態・未完了事項は作成当時の記録です。現在の仕様は共通カスタム台帳を参照してください。測定値は再集計せず保持し、個人ホームパスを匿名化しています。生ログ・個人設定は公開対象に含めていません。

2026-11-11 JST。ToR-O3 UD-IQ4_XS の第0層から読み取った `attn_qkv.weight`（10,240×2,560）と `attn_gate.weight`（6,144×2,560）を使用。両方 Q6_K。2区画とも4,096行で、再現可能な合成 F16 入力を使用した。第1・第2行は全ゼロとワンホット。

- GPU は Gufo `571c6b54` の最適化済み Q6_K／F16／FP32 積和カーネル。ToR-O3 の通常経路に合わせて QKV と gate を別々に投影した。
- NPU は mikealanni/gufo `223540e` 公開の4,096×2,560×1,024用プログラムを Windows XRT で実行。フォークの変換処理で16スライスを作り、4スライスまで同時にキューへ送った。GPU が第1区画を演算している間に、NPU が第2区画を演算した。NPU の出力を GPU に戻し、ブロック浮動小数点から FP32 へ展開した。
- 基準と並行版を同じプロセス内で順序を交互に入れ替えて測定。初回を除く6組の中央値。逐次版は別試行で、NPU の完了後に第1区画の GPU 演算を起動した。初回の Windows ポーリング待ちが大きい試行は予備記録に保存した。

| 4,096行×2区画 | 中央値 | 範囲 |
| --- | ---: | ---: |
| 現行 GPU（並行版と交互） | 24.27 ms | 23.74〜25.49 ms |
| GPU＋NPU、演算を順に実行 | 32.38 ms | 31.07〜32.95 ms |
| GPU＋NPU、演算を重ねる | 26.94 ms | 26.22〜27.47 ms |

並行版は GPU 単独より中央値で11.0%遅く、6組すべてで遅かった。並行版の区間中央値は入力の変換と送信1.84 ms、第1区画のGPU演算12.25 ms、演算後のNPU待ち4.68 ms、72 MiBの戻しとFP32展開8.28 ms。区間中央値の合計は全体中央値と一致しない。Windows のNPU発行から完了までの中央値は、逐次12.43 ms、並行15.48 ms。これは各スライスの発行と完了待ちを含む。

## 精度

第2区画の出力67,108,864要素を照合。全要素が有限で、GPUとNPUの相対RMSEは1.351%、RMSEは0.001568、最大絶対差は0.03279、コサイン類似度は0.999909。FP32 のビット列が一致したのは17,454要素。QKVのみの相対RMSEは1.348%、gateのみは1.358%。NPU の逐次出力と並行出力は全バイト一致。CPU のFP64参照で抽出640要素も照合し、GPUの最大絶対差は5.80e-6、NPUは0.00977だった。全モデルの応答品質と TTFT は対象外。

## 証跡

`summary.json` に時系列・比較値、`fixture.json` に実 GGUF のテンソル情報、`artifact-sha256.txt` に実行物・生出力のハッシュを収録。生出力・一時入力・ビルドは `/tmp/gufo-ssm-npu.4rryHR`。常用 Gufo は試験開始時と終了時に停止を確認した。試験用 Docker・Windows プロセス・WSLg 共有領域は終了と解放を確認した。採用条件の全バイト一致を満たさず、単層の速度も低下したため、統合の採用は見送り。
