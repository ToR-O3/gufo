# GufoへのNPU組み込みはNot Go

> 履歴資料：本文の採用状況・起動状態・未完了事項は作成当時の記録です。現在の仕様は共通カスタム台帳を参照してください。測定値は再集計せず保持し、個人ホームパスを匿名化しています。生ログ・個人設定は公開対象に含めていません。

ToR-O3 UD-IQ4_XS＋内蔵PLE、Strix Halo、Windows XRTとWSL＋Dockerの現構成で判断した。16K単一区画で融合GDNを維持する案、4K単位で展開を先行する案、共有ページ／GPU作業領域からBFPを直接読む案、２区画、8K幅、8層・16層への絞り込みを試した。試験コードは一時ディレクトリに隔離。通常のGufoは試験前後とも停止状態で、試験コンテナとWindows補助は終了を確認した。

- **ARの最有力版は、正式再計測で両方ともGPU単独より遅かった。** GPU16K幅のPrefill中央値は11.047／22.853秒、NPUは11.353／23.780秒。16Kで+2.77%、32Kで+4.06%。両長さでNPUの計測３回すべてがGPU対照３回の最も遅い値より遅かった。
- **層を絞るとRAMは下がった。** 全33層は約0.917 GiB、8層は0.504 GiB、16層は0.636 GiB。8層のPrefillは11.139／23.381秒。16KのGPU基準KLは全層0.520、8層0.639。速度順での選択では数値差は一様に減らなかった。BFPの読み方を変えた修正版は元のNPU版と両長さで全ロジット一致。
- **MTPでは実際にNPUが稼働した。** 17,426トークンの単独リクエストで132ジョブ、34,909トークンで264ジョブ。34,909トークンのTTFTは同じ16K幅のGPUで29.321秒、NPUで28.423秒、GPU8K幅で28.110秒。各１計測の結果。17,426トークンではGPU16K幅12.817秒、NPU14.042秒。並行生成時は実測で512トークン34パスと18トークンの末尾となり、NPUジョブはゼロ。再利用試験は17,426トークンをキャッシュから読み、Prefillゼロ。並行側の生成では335トークンのMTPドラフトを採用し、長文の３件の検索マーカーもすべて一致した。
- **WindowsとWSLの境界に大きな振れが出た。** 最初の単一区画試験では、投入から通知までのp99が約346 ms、Windows XRT内のp99が約8.4 ms。修正版で境界遅延が安定した試験でも、GPU単独に対する速度改善は再現しなかった。同条件のネイティブLinuxでの比較は未実施。
- **GPU単独の8K幅は別の改善候補。** MTPの単独TTFTは4K→8Kで17,426トークンが14.178→13.439秒、34,909トークンが30.245→28.110秒。並行ケースは29.901→30.021秒。読み込み直後のHIP空きは4Kから約1.48 GiB減少。16K幅では並行ケースが38.939秒だった。実用設定の採否を確定するための反復試験は今回の範囲外。

初期のBFPアドレス計算を修正し、無効な試験を明示して再試験した。GPU対照は試験コマンドの終了後にシェル構文エラーが出たため、全反復の生出力と別のGPU対照で照合。GPU4K幅の読込直後のメモリは補助プログラムの起動を修正して再取得した。
