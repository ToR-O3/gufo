# Q6_KゲートのNPU採否を判断する試験

> 履歴資料：本文の採用状況・起動状態・未完了事項は作成当時の記録です。現在の仕様は共通カスタム台帳を参照してください。測定値は再集計せず保持し、個人ホームパスを匿名化しています。生ログ・個人設定は公開対象に含めていません。

ToR-O3 UD-IQ4_XS＋内蔵PLE。Strix Halo、WSL＋Docker、ROCm 10.1、Windows XRT。前回と同じ実テキスト・コードから、ARのCLI試験は16,384／32,768トークンの先頭を使用。各長さの反復0はウォームアップ。GPU対照・既存の単一区画・8層部分分担は計測3回、他の候補は探索として計測1回。条件内のロジットは最初の計測から全語彙248,320個を保存。TTFTはCLIのPrefillと最初のトークンを返す処理の和。

NPU対象は内蔵PLE後のQ6_Kゲート。入力4,096×2,560と出力4,096×6,144をBFPで交換。FP32に展開する経路で、各4Kグループの完了直後にサイドストリームで展開を開始する方式を比較した。BFPをGDNの既存の融合カーネルで読み取る方式は、共有ページからの直接読みと、BFPをGPUの作業領域へまとめてコピーする方式を比較した。後者は同じ作業領域を使う。GPUカーネルの算術はゲートの読み出し以外を維持した。NPUの加算はBFPであり、GPU単独のGGUF投影と数値差が生じる。

16K単一区画のGPUと、展開を先行させたNPUの両方で、GPUのHIPイベントから各層の投影開始からGDN終了までを計測した。ウォームアップを除いた各層3パスの中央値の差で並べ、上位8層と16層を実際に登録・分担した。単体試験の合成入力結果を参考列に掲載。層の選択にRAM上限は使用していない。

HTTPはループバックの試験用Docker。2セッション、各131,072コンテキスト、MTP共有Q8_0、ドラフト7、競合時のプリフィル512、RAMキャッシュ4 GiB。テキストのみで、リクエスト時に思考を無効化し、greedy。孤立した長文２長、片方が生成中に長文を投入、同じ長文をRAMキャッシュから再利用、の各ケースを試した。長文はCLIと同じコーパスに離れた３箇所の検索マーカーを追加したチャット入力であり、実トークン数をHTTPのusageから保存する。速度比較の反復0はウォームアップ。出力に現れたマーカー、ドラフトと採用数、先頭SSE出力までの時間、サーバのPrefill、並行生成時のSSEチャンク間隔を保存した。SSEチャンク間隔はトークン間隔と同義ではない。

## 証跡

- `summary.json` に各反復、品質、メモリ、HTTPの利用量・タイミング・NPU使用件数。
- `projection-by-layer.csv` と `rank-layers.csv` に実モデルの層別区間、`bridge-per-job.csv` に送信、Windows側XRT、完了通知、受信。異なるOSのUNIX時計を使った遅延は時計差を含む。XRTの処理時間は同じWindows時計で測定。
- `logs/` にDocker、WSL、Windows生ログと失敗、`logits/` にロジット原本、`harness/` に再現手順と前回試験版からのコード差分。GPU初期化時の空きの差、Dockerのcgroupメモリ、Windowsのprivate commit、共有領域とHIP固定領域は各々異なる観測範囲。追加RAMは同じ共有ページを一度だけ計上した。
- 初回のBFPアドレス式にはタイルのグループ数の誤りがあった。旧版の直接読みとGPU作業領域版を無効化し、全524,288グループ・各2つのfloat4アドレスを既存展開式と照合して再実行した。旧版の速度・ロジットを候補の比較に使用しない。
