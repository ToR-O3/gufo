# 2026-11-11 NPU 出力の GPU 直接参照

> 履歴資料：本文の採用状況・起動状態・未完了事項は作成当時の記録です。現在の仕様は共通カスタム台帳を参照してください。測定値は再集計せず保持し、個人ホームパスを匿名化しています。生ログ・個人設定は公開対象に含めていません。

現行の WSL＋Docker（gfx1151、ROCm 10.1）で Windows XRT と GPU が同じバッファを使えるかを確認した。ToR-O3 UD-IQ4_XS＋内蔵 PLE の GGUF 4分割のヘッダーも調べた。使用した参考実装は mikealanni/gufo の `223540e2f075d3d273eda6588ec458f21cdda083`。単層コピーありの前回結果は隣の `20261111-ssm-in-npu` にある。

| 試験 | 結果 | ログ |
| --- | --- | --- |
| WSL 内の HIP 固定メモリと通常の匿名共有メモリ | GPU カーネルが直接読み書き。CPU がパターン一致を確認 | ordinary.log |
| Windows XRT と共有できる WSLg の DAX ページ | 4 KiB で HIP の登録オプション5種、72 MiBで通常のマップ登録を試した。すべて `hipErrorInvalidValue`。下位の `hsa_amd_memory_lock` も両サイズで拒否 | dax.log |
| WSL GPU の確保領域を Windows に書き出す | POSIX ハンドルの発行と同じ WSL 内での再オープンに成功。HIP の Win32 と Win32 KMT は未対応。WSL ドライバの `LX_DXSHAREOBJECTWITHHOST` は対象リソースを `EINVAL` で拒否 | export.log |
| Windows 上のファイルを Windows と WSL の両方でメモリマップ | 初期値は見えたが、マップ済み領域への更新は明示同期なしでは両方向とも見えなかった。一時ファイルは削除済み | drvfs.log |
| Windows 内の HIP 固定メモリを XRT に登録 | GPU カーネルが書いた BFP の入力を NPU が読み、4,096×2,560×1,024 の参考 fork カーネルの BFP 出力を GPU カーネルが同じページで直接照合。入力同期ありなら出力側の `bo.sync` も省け、3回すべて4,194,304要素が一致。入力同期なしでは不一致 | windows-native-{both,input,output,no-bo-sync}.log |

Windows 側は NPU と GPU の間にアプリによるデータコピーを挟まず、GPU の実行完了待ち、XRT の入力同期、NPU の実行完了待ちを行った。診断の入力は全要素が1または0の BFP で、出力期待値は2,560または0。出力一致はテストパターンについての確認。ToR-O3 の数値精度を評価する試験ではない。初回の Windows 診断は演算照合後に XRT の終了処理で例外が出た。XRT オブジェクトを先に明示解放する順序に修正し、演算と終了の両方が通った。WSLg の初回は起動引数の誤りでブローカーがタイムアウトしたため、引数を修正して再試験し両方の一時領域の解放を確認した。

参考実装の `device_model.cpp` は `ssm_in` または `attn_qkv` が Q8_0 であることを NPU の全投影経路の準備条件とする。`executor.cpp` は PLE 後の残り全層にそのバッファがあるときに同経路を使う。ToR-O3 は 0 始まりの PLE 層 1 の次から46層中1層だけが Q8_0。Q6_K を追加対応し、固定カーネル用のBFP重みを参考実装と同様に46層分常駐させる場合、投影重みだけで2,064,384,000バイト（1.923 GiB）の計算値になる。作業領域、その他の投影、ドライバ、実測の物理RAMはこの数字に含まない。詳細は `model.json`。

現行 WSL＋Docker で全モデルの同等経路は組めず、16K／32Kのプリフィル、TTFT、モデル精度、追加RAMの実測は未実施。今回、計測したのは共有メモリへの直接アクセスと Windows 内の同じページでの投影動作。前回のコピーあり単層の +11.0% は別経路の測定結果。Gufo の実装と常用コンテナに変更は加えていない。常用コンテナは開始時と終了時に停止を確認した。

`harness/` は診断ソース。Windows で使用した XRT 拡張・Python・参考 fork の固定カーネル一式、およびビルド済み実行物は `/tmp/gufo-npu-direct.EH0gUj` に保管。ソースとログのチェックサムは `SHA256SUMS`。
