# Huihuiの通常PLEを外部Q8へ変更

> 履歴資料：本文の採用状況・起動状態・未完了事項は作成当時の記録です。現在の仕様は共通カスタム台帳を参照してください。測定値は再集計せず保持し、個人ホームパスを匿名化しています。生ログ・個人設定は公開対象に含めていません。

採用日時：2026-11-06T11:17:54.759623+09:00

ユーザー指示により、通常Gufoの外部PLEをBF16からQ8_0へ切り替えた。Gufo本体のソースとイメージは変更していない。従来の通常設定から変更した引数は`--ple-model`の値だけ。

- イメージ：`gufo:v0.30.0-reviewed-c1170a4a-rocm101`（c1170a4a、ROCm 10.1）
- モデル登録名：`Qwen3.8-FN-UD-IQ4_XS`
- PLE：`/models/PLE/Qwen3.8-Flash-Next-PLE-Q8_0.gguf`
- 通常設定：2セッション×131072、thinking auto→on、MTP max7/min1、prefill512、RAMキャッシュ4 GiB、共通mmproj、AMD_SERIALIZE_COPY=2、Docker on-failure:3を維持。
- 次回のDocker起動も作成済みの`Gufo`コンテナが同じQ8構成を使う。再作成時はAppsの`normal-settings.json`と作成引数（ローカル保管：docker-create.json）を使う。
- ASRは同じコンテナ・同じ設定・同じ停止時刻を維持。

確認記録（ローカル保管：verification.json）でAPI、モデル名、Q8ファイルの実マッピング、通常引数と環境・マウント・Docker設定の同一性、短文応答を確認。追加ベンチは実施していない。既存の回答一致課題を解消したという意味ではない。

Q8ファイルは既存の公開SHA-256照合済み配布物を再利用。今回の切り替えでは54.4GB全体の再ハッシュや再ダウンロードを行わず、サイズと稼働プロセスの参照先を確認した。BF16ファイルと過去のベンチ記録は保持している。
