# Gufo v0.30.0：カスタム整理とBF16比較

> 履歴資料：本文の採用状況・起動状態・未完了事項は作成当時の記録です。現在の仕様は共通カスタム台帳を参照してください。測定値は再集計せず保持し、個人ホームパスを匿名化しています。生ログ・個人設定は公開対象に含めていません。

対象：9c6ab4b6 → c1170a4a. ROCm 10.1、gfx1151、AMD_SERIALIZE_COPY=2。通常Gufo常駐下の演算試験で、1秒間隔のスロット監視では要求の重なりを観測していない。

## 項目8の追加点検

小行列の独自追加は、既存SmallBatchKQuantExactFp32GEMMKernelへのGroupedGrid（既定false）とグループごとの入力／出力先調整、対象形状のランチャー。古いカーネル本体の複製はない。8行単位のグループと端数の公式ランチャーへの委譲を維持する。独自の起動設定は残っており、公式の全ての形状別設定を自動適用する意味ではない。カーネル内部の新しいスケジュール分岐も、テンプレート条件が一致する場合だけ適用される。今回、速度未検証の起動設定変更は加えていない。shared expertの追加は既存SwigluHalfへ最終積のFP32丸め境界を保つ選択を加え、既存の専用FP16作業領域を使うもの。保存済みおよび今回の試験で、旧単純融合14点の差に対して境界維持経路は0点。不要な旧カーネル複製は見つからなかった。

## BF16経路の比較

同一BF16データ、FP32出力。35通り（5形状×7分割）の全出力を比較。FP64参照は各条件32点を抽出。時間は各条件3回、GPUイベント、重みを64 MiB以上で巡回。モデル全体のPrefill／TTFT／Decodeではない。

|入力→出力|固定順序 ms（512行）|hipBLASLt ms（512行）|固定順序の分割不一致|hipBLASLtの分割不一致|固定順序FP64最大絶対差|hipBLASLt FP64最大絶対差|
|---|---:|---:|---:|---:|---:|---:|
|10240→320|0.307917|0.611705|0|39,245|0.001661002636|0.001760184765|
|320→10240|0.207121|0.650542|0|850,479|2.384185791e-06|2.205371857e-06|
|2560→10240|1.130573|4.891923|0|1,221,160|0.0001657009125|0.0001428723335|
|2560→2560|0.284362|1.224897|0|305,143|9.399652481e-05|0.0001054406166|
|2560→512|0.070306|0.302451|0|60,990|9.936094284e-05|0.0001400709152|

採用：有効なHC／PLEの4形状は固定順序経路を維持。512行では約2.0〜4.3倍短時間で、7種類の分割でも全出力がビット一致。hipBLASLtは128行のHC downで速い条件があるが、分割による数値差があるため採用しない。FP64との差は形状によって優劣が異なり、固定順序が全条件で参照へ近いという結論ではない。
