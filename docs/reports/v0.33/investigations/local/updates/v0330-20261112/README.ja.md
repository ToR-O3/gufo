拡張APIの互換性確認で、forkの既存契約に `TextRunnerOptions::ple_model_path` が含まれることを確認した。後続の `e55f3b29` は、CLIを本家のプロバイダー設定に保ち、直接APIを呼ぶ拡張向けの旧フィールドとフォールバックを残す。両方を指定した場合はプロバイダー設定を優先する。書式949ファイルと拡張API 0.2.23の差分検査が合格。正式性能測定の初回ビルドは `2ffecf82`。

通常起動の `--prefill-chunk 512` は削除する。v0.33.0は指定を無視し、モデルのスケジューリングプロファイルからパス幅と層分割を自動決定する。対応する置換フラグはない。

書式949ファイル、文書158ファイル、Qwen依存関係、拡張API 0.2.22を検査。Nixのロック指定でv0.33.0の全拡張入りパッケージをビルドした。ビルドと配布作業の原記録はこのディレクトリに、ベンチの生ログと公式参考値は `docs/benchmark/runs/v0330-toro3-20261112` に保存する。

## 実機測定

内蔵PLE＋MTP、外部PLE Q8_0＋MTP、内蔵PLE＋DFlash2を各3回測定した。[比較表](../../../../benchmarks/benchmark/reports/v0330-toro3-20261112/report.ja.html)と[集計・生ログの入口](../../../../evidence/benchmark/runs/v0330-toro3-20261112/summary.json)。本測定は `2ffecf82`。公式参考値はv0.33.0タグに収録された別量子化の公表値。

- 内蔵PLE＋MTPの通常文2セッションは本測定7.51 tok/s。旧版の同一入力追試は47.67 tok/s、更新前のDFlash2統合試験ビルドは50.14 tok/s。v0.33.0を独立起動した追試は44.03 tok/s。HIPグラフを1キューに限定した追試は43.07 tok/sで、速度改善は確認できなかった。初回の低速状態の発生条件は未特定。
- 外部PLE＋MTPの通常文は4セッションで11/12、6セッションで17/18が単独ARと一致。いずれも追試で同じ一致件数だった。外部PLEの単独AR同士・MTP同士は、それぞれ旧版と24/24件一致。
- DFlash2の同時利用は通常文・反復文で126/126件が単独ARと一致。比較用ARの2セッションは初回5/6件、追試6/6件。履歴付き単独生成は通常文21件、反復文21件が11月10日のDFlash2保存出力と全件一致。
- `e55f3b29` のNixリリースビルドは3構成のロード・生成・ドラフト動作を再確認。内蔵PLE＋MTPの通常文2セッションは独立起動2回で46.90と46.74 tok/s、単独ARと計12/12応答が一致した。正式な全測定と本ビルドの追試は報告で区別した。

## 通常運用の判断

v0.33.0 `e55f3b29` は通常起動してAPI応答、MTP生成、層分割を確認した。8,139トークンを別の生成と同時に処理し、最大4,096トークンのパスを最大8層グループへ分割、生成へ16回処理を戻した。

通常の2セッション・128K・キャッシュ4 GiB・画像プロジェクターありで、短い単独生成の直後に通常文2件を並行実行。v0.33.0は最初の実運用構成で8.22 tok/s、同じウォームアップを行った再起動で7.83 tok/s。v0.31.0は同じウォームアップ後で49.24 tok/s。いずれも各3回で、測定した生成は単独ARと一致した。

同一の診断ビルドでは、先行する単独生成を省くと44.92 tok/s、単独生成の後は自動選択の直列で7.84 tok/s、並列を強制して7.55 tok/s、HIPグラフを1キューに限定して8.00 tok/s。短い単独生成で低速を再現できた。共有エキスパートの並列化とHIPグラフのキュー限定で解消せず、低速になる内部経路は未特定。

常用採用は保留し、元のコンテナ `gufo:v0.31.0-quant-refactor-96f1aa8c-rocm101` を通常設定で起動した。APIのready、モデル名、生成、ドラフト採用35/56を再確認。通常設定2ファイルは作業前と同一。v0.33.0ソースは作業ツリー `codex/update-v0330-ple-compat` の `e55f3b29` に保存。試験用の起動や設定は作業終了時に解消した。稼働確認（ローカル保管：final-runtime.json）。
