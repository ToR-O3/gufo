# 固定入力・PLE各3回の追加測定

> 履歴資料：本文の採用状況・起動状態・未完了事項は作成当時の記録です。現在の仕様は共通カスタム台帳を参照してください。測定値は再集計せず保持し、個人ホームパスを匿名化しています。生ログ・個人設定は公開対象に含めていません。

対象はUnsloth v3.1系 IQ4_XS（Orca重み移植版）。ユーザー指定で同時利用を除き、AR文章・MTP文章・MTP反復を、0/4/8/12/16/32/64/128Kの履歴深度ごとに外部Q8_0 PLE／内蔵PLEで各3回測定する。測定後は既存のGufoコンテナを内蔵PLE・通常設定へ戻す。実行時間を次回の回数判断に使うため、各工程の時間と1/2/3回での集計の違いも残す。

## 条件

- 本体はv0.31.0、96f1aa8c、実行ファイルSHAはmanifest.json。ソース・通常設定は変更しない。
- 公式HTTP要求・計時・サーバー管理の部品を利用し、反復ごとの入力変更を取り除いたローカル制御を使用する。
- 入力と履歴はcorpus.jsonに固定。assistant履歴も固定文字列で、準備時の生成回答は測定履歴に採用しない。
- 1セッション、context133760、thinking off、greedy、seed1、約2048追加token・128生成token。
- 現在の正式設定はRAMキャッシュ8GiB。各8深度の組ごとにサーバーを再起動し、同じ別入力でウォームアップする。深度ごとに前置きをcoldで作り、短い無関係なcold要求でlive状態を退避してからRAM状態を復元する。実際の再利用経路とトークン数を検査する。
- PLEの順序と処理の順序を反復番号の偶奇で逆転する。中央値・IQR・全値・平均・SD・範囲を保存し、極端な値だけを除外しない。
- 起動速度と専用メモリ負荷の追加スイートは実施せず、144件の単独測定中のメモリと起動等の準備時間を記録する。

## 初期設定の不成立

最初の4GiB設定では、MTPの128K履歴をlive退避後に保持できず、63,488 tokenから再計算した。要求は69,486 tokenを新規処理し、約2Kという条件に違反した。最初の24件はformal/とattempt-4gib/に全件保存し、現在の8GiB正式集計と混ぜない。これは外れ値除去ではなく条件不成立での揃え直し。通常起動のキャッシュは従来の4GiBへ戻す。

## 記録

- manifest.json：条件と実行ファイル・ハーネスのSHA。
- active-job.json、formal-run.log：進行状況。
- formal-8gib/：正式測定。各組に入力、回答SSE、キャッシュ準備、実測、サーバーログ、HIP監視。
- formal/、attempt-4gib/：容量調整前の24件と失敗理由。
- pilot/：初期の2深度予備確認、正式回数に含めない。
- normal-container.before.json、normal-settings.before.json：復帰元。コンテナを作り直さず同じGufoを起動する。
- harness/restore_normal.py：通常復帰と設定・API確認。復帰前に試験用モデルプロセスが終了していることを確かめる。
- monitor.py：Windows・WSL・Docker監視。通常復帰後のメモリ取得後にstop-telemetryを作成して終了する。
- harness/analyze.py、memory_summary.py、duration_summary.py、repetition_comparison.py、report.py：原記録から再集計可能。

所要時間は正式測定、予備確認、容量調整前の試行を区別する。1/2/3回の比較は同じ3観測の記述統計であり、3回の中央値を真の性能とは扱わない。最終確認前は完了と扱わず、formal-completion.jsonとnormal-restored.jsonの両方を確認する。

ユーザーが途中で合計3回へ変更。前回3回は条件が異なるため別に比較する。初期の10回計画は取り消し、4回目を起動前に止めるガードを設定済み（stop-after-r03.json）。5回・10回の所要時間を記す場合は推計と明示する。

## 完了記録

正式144件・18組を完了。全48条件で3回答が一致し、AR／MTPも各PLEで24/24一致（8入力×3回）。4回目は開始前に停止し、既存のGufoを内蔵PLE・通常設定で復帰した。正式測定1時間39分51秒、記録開始から復帰まで2時間6分39秒。全値を保持し、代表値は今回3回の中央値。前回3回とは別集計。最終確認はreport-validation.json、復帰はnormal-restored.json、要点はfindings.json、時間の内訳はduration-summary.jsonを参照。Windows側メモリは2要求で監視サンプルがなく、欠測として保持。速度・回答の欠損はない。
