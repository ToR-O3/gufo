新キャッシュと4GiB現在の設定独自改修との関係検証初回遅延生データ

4GiBは今後も残すべきか

今回の使い方では、4GiBの明示指定を残すことを推奨します。新キャッシュは保存・再利用の仕組みを置き換えるもので、従来の4GiBとは別にもう一つ容量を積むものではありません。4GiBは、新しい仕組みに与えるRAM予算です。

項目役割今回の意味
実行中・直前の状態各sessionが持つKV、再帰状態、MTPなど計算を進めるために必要。互換の続きなら、その場で再利用できる。
新しい会話キャッシュその状態を部品単位で保存・共有し、適合する再開位置を選ぶ管理方式v0.14でFlash-Nextが自動的に切り替わる。別の容量設定が増えたわけではない。
cache-ram-bytes 4GiB上記の保存領域のRAM上限checkpoint、KV行、端数、退避、管理情報をまとめて制限。会話切り替えや過去の位置からの再開に役立つ。
sessions 2実行用の状態を2組持つ設定保存できる会話を2つに限定する設定ではない。会話数と保存量は長さ・共有・保持位置で変わる。
n-gramキャッシュモデル内の別の表キャッシュ（128 MiB）今回の4GiB会話キャッシュとは別。v0.14での新設ではない。

新方式では、checkpointごとにすべての状態を丸ごと重複保存することを減らし、共有できるKV行と、その位置固有の再帰状態などを分けて扱います。実行用の行を参照しておき、上書き前に退避する場合もあります。保存済みの互換checkpointから再開し、未計算の後続だけを処理します。単純に「現在の会話にはキャッシュを使わず、別の会話だけが4GiB」と二分するのは正確ではありません。

会話を戻したり、直前より前の位置から再開したりする用途で保存領域は有用です。ただし4GiBが推論の必須容量、最低容量、最速となる最適値という意味ではありません。足りない場合は保持できる位置が減り、再計算が増えます。4GiBで128Kの会話を何本でも残せる、あるいは2本確実に残せるという保証もありません。

容量の扱い今回の値・判断
現在の上限4.000 GiB
今回の再試験後の管理対象RAM3.601 GiB。未使用の確保済みページも含む値で、保存データだけの量ではない。
指定なし / 0の場合自動設定。今回の起動ログでは 12.05 GiB。無効化ではない。
起動時に報告された明示設定の上限20.10 GiB。空き状況から出た許容上限であり、推奨設定値ではない。
確保方法必要に応じ約1GiBずつ増え、確保したページは保持。予算の約89%をページ領域、残りを管理情報に使う。
容量を増やす判断会話復帰のmiss・再prefillが多く、実際の空きメモリに余裕がある時に検討。今回の更新を理由に増量する必要はない。

自動容量はモデルと状態の確保後の利用可能ホストRAMの半分、最大32GiB。明示容量もホストRAMを4GiB残す範囲に制限されます。WSL・コンテナの制限が関わり、Windowsの搭載RAMから単純には求められません。今回の4GiBは、以前の「8GiBでは余裕が心もとない」という運用方針にも合います。GPU表示・RSS・この管理値には参照や共有があるため、無条件で足して総物理使用量にはしません。

根拠：v0.14.0 KV-CACHE / Flash-Next budgets、SERVER、実機のconfiguredログ。旧方式の説明やRFCの将来計画は、出荷済み実装と区別しています。

A・Orca対応と本体更新の関係

対象取り込み方針と結果
公式の新キャッシュ新しいキャッシュ本体・Flash-Nextの保存/復元アダプター・レイアウトはv0.14.0のまま。独自改変なし。
A採用済みの正確なF16直接出力を維持。一時作業バッファの処理なので、永続化する状態の形式を変更しない。
Orca IQ4_XS / MTP / Vision引き続き必要。既存の量子化演算・sidecar読込対応を保持し、公式の計測付きメモリ割り当てへ接続。
衝突の解消device_model.cppは公式WeightAllocatorと容量計測を優先。既存の互換変換にも計測専用経路を付け、実際の変換後容量を報告。算術は変更しない。READMEは両方の試験説明を保持。
B1・B2・C今回は不採用のまま。別ブランチ・記録を残し、更新ブランチには含めていない。

変更の基点は採用済みAのブランチです。公式v0.14.0とAは更新後の履歴に含まれ、B1・B2・組み合わせ・Cの実装commitは含まれません。今回の数値演算経路は採用済みAと同一です。将来の本体更新も、IQ4への接続と丸めの条件を確認して取り込む必要があります。

動作・出力の確認

  • キャッシュ・継続レイアウト・メモリ割り当てを中心に、CPU 11件とGPU 3件が合格。
  • 旧v0.13と新v0.14をそれぞれ再起動して確認。短文、同時2件、seed固定sampling、会話切り替え、継続、32K、Visionの17応答で本文と終了理由が一致。
  • 2つのlive sessionを別会話で置き換えた後、RAMから175,102,288 bytesを復元し、1,580入力tokenを再利用。新キャッシュの実利用を確認。
  • 32,764 tokenの入力・再送・継続、実際のMTP draft、画像中の文字と色、公式のキャンセル後の再開試験を確認。
  • フル128Kの新規速度試験、AR、同時128K、ディスク永続化、全モデルlogit/teacher照合は今回の範囲外。

32Kの同じ入力を再送した際は、旧版が7 tokenを再prefillしたのに対して、新版は32,764 tokenすべてを再利用しprefill 0でした。Vision再送も201 token全体を再利用しました。これは今回の入力での結果で、すべてのチャットや編集で完全再利用できることを保証するものではありません。
