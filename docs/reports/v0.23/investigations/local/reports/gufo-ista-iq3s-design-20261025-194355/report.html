結論

この方針で進める合理性があります。ISTAとSC117のIQ3_Sは構造が共通で、別エンジンや作者別の演算分岐は必要ないと判断します。通常行列はGufoの共通GEMMへ接続し、専門家は公式の演算構造に必要な量子化形式だけ追加する案です。

ただし、公式v0.23.0だけで必要な全形式を処理できるわけではありません。IQ2_S・IQ3_XXS・Q2_0等への対応は必要です。旧SC117専用方式を廃止することと、必要な形式の復号機能まで失うことは分けて扱います。

今回は調査と設計まで。ソース改修、モデル切替、推論試験、再起動は実施していません。稼働中のOrca用Gufoは同じコンテナ・プロセス・設定のままreadyです。

3. 削除・維持・追加する範囲

領域方針内容
旧互換方式廃止--weight-compat、WeightCompat、requantize_q8、SC117の206行列allowlist、Q8再量子化とその専用分岐を撤去。黙って変換する代替経路も作らない。
通常の量子化行列既存Gufo経路を再利用Flash-NextのNativeIq4Denseから呼ぶ共通GEMMを使う。Q4_Kを接続し、Q6_Kを必要な通常行列へ許可する。Q5_K・IQ4_XS・IQ4_NL・既存Q6_K出力ヘッドを再利用。
専門家の低ビット形式必要分だけ共通演算へ接続公式RoutedF16GEMM・MMQ/MMVQの構造に、IQ3_S版に必要なIQ2_S・IQ3_XXS・IQ3_S・Q2_0等を接続する。旧SC117コードを無条件に残さず、コードブック、符号、ブロック幅、丸めを再監査する。
浮動小数点のアップロード共有処理を分離して維持BF16等の小行列スタックとPLEのF16→F32はQ8再量子化と別。Orcaでも使う必要な処理・丸めは維持し、weight_compatという名前への依存を解消する。
対象モデルISTA / SC117 のIQ3_S実行経路は作者名で分岐せず、役割・GGUF型・形状・ブロック境界で選ぶ。今回は両者のIQ3_S配置だけを検証・サポート対象にする。
将来拡張型の実装とモデルの検証対象を分離IQ3_XXS版などは、配置表追加→不足する役割／型を確認→独立検証という同じ手順で追加可能にする。内部にIQ3_XXS演算があることを、IQ3_XXS版モデル全体の対応と混同しない。

旧オプションは通常設定にも --weight-compat off として残っています。新実装へ移行する段階で、CLI・実行コード・新しい起動設定・ベンチ後の復帰手順を一緒に直します。過去の実測記録に残る引数や結果は履歴として保持します。

必要な形式を追加する場所はGufoの既存の型定義・復号・行列演算です。SC117だから変換するという条件や、新しい独立エンジン／汎用プラグイン層は作りません。未対応の役割・型・形状は早い段階で明示的に拒否します。

4. 実装順序と合格条件

  1. 基準を固定：公式v0.23.0と採用済みOrca/Aを基準に、現在の二つのIQ3_S配置表を試験資料にする。旧SC117コードから残すものを機能ごとに説明可能にする。
  2. 通常行列を接続：Q8再量子化なしで読み込み・アップロード・通常行列の演算を通す。型変換と割当て容量の計測も一致させる。
  3. 専門家演算とモデル全体を検証：必要な量子化形式を公式構造へ接続し、独立した演算基準→AR→MTP・継続状態の順で確認する。
  4. 旧互換機能を撤去：最終成果物からCLI・フラグ・allowlist・再量子化を削除し、Orca回帰と復帰手順を確認する。途中段階を採用済みランタイムに混ぜない。
  5. 性能判断：品質が合格してから速度とメモリを比較し、採用判断用に報告する。未採用最適化は別実験として扱う。
